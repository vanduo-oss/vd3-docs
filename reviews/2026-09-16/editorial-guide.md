# DocSite voice

Write for a developer or agent trying to complete a task. State what the component
is for, show it, then provide a complete example. Follow with the API and the
constraints that change how someone uses it.

- Open with one or two sentences. Put demo-specific controls beside the demo.
- Prefer a Vue example first. Label CSS-only and composable examples explicitly.
- Include the imports, stylesheet choice, data, and relevant event in a copyable example.
- Explain defaults once, in the API table. Distinguish demo settings when they differ.
- Use concrete feature descriptions. Avoid blanket accessibility, security, and performance claims.
- Put maintainer build/release rules in contributor documentation, not consumer pages or skills.
- Keep useful constraints: state ownership, SSR boundaries, cleanup, focus, and invalid-input behavior.

Do not add sections to a page that is already concise. Do not turn an optional
variation into a second tutorial. The first pass shortens Dock, Doc Search,
Theme Customizer, Flowchart, Charts, Ecosystem, and the entry/install guides;
future edits follow the same voice.
